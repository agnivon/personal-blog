This project uses [Convex](https://convex.dev) as its serverless backend and autonomous task scheduler, [Sanity CMS](https://www.sanity.io/) as its content lake, and [Google Gemini](https://ai.google.dev/) via `@google/adk` and `@google/genai` for multi-agent content generation.

When working on Convex code, **always read `convex/_generated/ai/guidelines.md` first** for important guidelines on how to correctly use Convex APIs and patterns.

- **Strict Type Safety**: Use Convex's schema definition (`convex/schema.ts`) to enforce strict type checking across all tables. Always import and use `v` validators (`convex/values`) to validate incoming arguments for queries, mutations, and actions.
- **Architecture Separation & AI Workflows**: Write queries and mutations for fast, deterministic database reads and writes. Always execute external network requests, Google Gemini / Google ADK pipelines, and Sanity CMS mutations within Convex `actions` (`convex/actions.ts`), never in queries or mutations.
- **Node Runtime in Actions**: Always add `"use node";` at the top of action files using Node.js modules, `@google/adk`, `@google/genai`, or Sanity client mutations. Never add `"use node";` to files exporting queries or mutations.
- **Internal vs. Public Functions**: Use `internalAction`, `internalQuery`, and `internalMutation` for scheduled jobs (`convex/crons.ts`), background generation, and backend maintenance. Never expose secret-consuming endpoints or generation actions directly to the public client.

## 1. Package Management & Tooling

- **Always use `yarn`**: Never run package-level commands using `npm`, `pnpm`, or `bun`. This project is configured with Yarn 4 Berry (`yarn@4.6.0`).
  - Install dependencies: `yarn install` / `yarn add <package>`
  - Run development server: `yarn dev` (runs `convex dev` and `next --turbo` concurrently)
  - Run individual dev services: `yarn next-dev` or `yarn convex-dev`
  - Sanity TypeGen: `yarn typegen` (`sanity schema extract && sanity typegen generate`)
  - Automated tests: `yarn test:once` (`vitest run`), `yarn test` (`vitest`), `yarn test:coverage`
  - Linting: `yarn lint`
  - Type checking: `yarn tsc --noEmit`
- **Agent Skills**: Manage AI agent skills using `npx skills` (e.g. `npx skills list`, `npx skills add <package>`). Always preserve `skills-lock.json` and `.agents/skills/`.

## 4. Convex Backend & Autonomous Publishing Standards

- **Strict Separation of Concerns**:
  - `convex/schema.ts`: Single source of truth for database table definitions (`topics` table with `by_generationDate` index).
  - `convex/queries.ts`: Deterministic read operations (e.g. `getTodaysTopics`).
  - `convex/actions.ts`: Outbound network I/O, AI model calls, and Sanity CMS publishing.
  - `convex/crons.ts` & `convex/jobs.ts`: Autonomous scheduled cron jobs running on UTC schedules.
- **Scheduler & Rate-Limit Protection**:
  - When triggering multiple generation jobs in `convex/jobs.ts`, always use `ctx.scheduler.runAfter` with staggered offsets (e.g. `idx * 60 * 1000`) rather than running unbounded parallel tasks to avoid exceeding external API rate limits.
- **Internal Action Protection**:
  - Autonomous workflows that create, generate, or publish content must be declared as `internalAction` or `internalMutation`. Never expose unauthenticated mutation endpoints that allow external callers to trigger freeform AI generation or database writes.

## 5. Google ADK & Gemini Multi-Agent Pipeline

- **Modular Agent Architecture (`convex/_lib/adk/`)**:
  - `researcher`: Conducts factual topic research with live Google Search grounding.
  - `architect`: Creates structured `ArticleBlueprint` with section outlines, word count budgets, and focal points.
  - `writer`: Drafts each section sequentially to maintain narrative continuity without context exhaustion.
  - `editor`: Reviews full drafts, polishes transitions, and enforces style guidelines.
  - `seo`: Generates metadata, search-optimized slugs, excerpt, and relevant tags.
  - `imageDirector` & `imageGeneration`: Crafts detailed image generation prompts and invokes Gemini Image model for cover art.
- **Schema-Driven Structured Output**:
  - Always validate agent outputs with Zod schemas (`ArticleBlueprintSchema`, `ArticleMetadataSchema`, `BlogGenerationConfigSchema` in `convex/_lib/adk/types.ts`).
- **Grounding Attribution & Inline Citations**:
  - Preserve Google Search grounding attribution chunks and citations. Extract and format source references into structured cards attached to the post.

## 6. Sanity CMS & Portable Text Standards

- **Schema Architecture (`sanity/schemas/`)**:
  - Documents: `post.ts` (title, slug, content, excerpt, coverImage, date, author, tags, sources, hide) and `author.ts`.
  - Singletons: `settings.ts` (site title, description, OG image, footer).
- **Portable Text Integrity**:
  - AI-generated Markdown and HTML must be converted into valid Portable Text blocks using `@portabletext/block-tools` (`htmlToBlocks`) and custom block deserializers in `convex/_lib/sanity.ts`.
  - On the frontend, always render Portable Text via the `<PortableText>` component (`components/portable-text.tsx`). Never inject raw, unsanitized HTML directly into the DOM.
- **Strict Post Publishing Mandates (Canonical Publication Standard)**:
  - When publishing or importing posts (e.g. via `.agents/skills/gdoc-to-post/`):
    1. **Line Breaks Must Be Preserved**: Distinct paragraphs must remain separate Portable Text blocks (`style: "normal"`). Blocks with trapped newlines must be split with `splitBlocksByNewlines()`. Soft line breaks are rendered via `<br />`.
    2. **Tables Must Be Displayed As Is**: Tables must be preserved and rendered as native Sanity `table` and `tableRow` objects. Never convert tables to bullet lists or summaries unless explicitly instructed otherwise.
    3. **Works Cited Must Be Displayed As Is**: The full numbered bibliography must be rendered in the body under `#### Works cited` and synchronized uncapped to `post.sources`, unless explicitly instructed otherwise.
    4. **Cover Image Preservation & Parity**: Never overwrite or delete existing cover art (`existing.coverImage`). Propagate existing cover art across datasets to maintain visual parity.
    5. **KaTeX Currency Escaping**: In LaTeX math mode, all literal currency symbols must be escaped as `\$` to prevent KaTeX red error rendering.
    6. **Diagrams and Flowcharts Must Be Represented Cleanly**: Never leave raw ASCII box art in published posts. Transform flowcharts into responsive Neo-Minimalist components with stage badges and icons.
    7. **Table Cell Entity & Math Hygiene**: Ensure mathematical inequalities (`>`, `<`) in table cells do not leak raw HTML entities (`&gt;`, `&lt;`) into KaTeX or the DOM.
    8. **Publication Timestamp**: Always set `date: new Date().toISOString()` on publish/patch so newly imported posts sort properly as the Featured Post on the homepage.
- **Next.js 16 Visual Editing & Draft Mode**:
  - Real-time preview is mounted via `presentationTool` with `defineDocuments` and `defineLocations`.
  - In `app/(blog)/posts/[slug]/page.tsx`, `generateStaticParams` must use `perspective: "published"` and `stega: false` to ensure clean, un-encoded slug strings during static export.
  - Embedded Sanity Studio is mounted at `/studio` (`app/(sanity)/studio/[[...tool]]/page.tsx`). Preserve the studio routing structure.

## 8. Code Quality & TypeScript Standards

- **Strict & Comprehensive Type Safety**:
  - **Zero `any` Policy**: Never use `any`, `as any`, or implicit `any`. Use `unknown` with type narrowing, Zod schemas, or Convex `v` validators.
  - **Leverage Generated Types**:
    - Sanity: Import generated types from `sanity.types.ts` (`Post`, `Author`, `Settings`, `PostQueryResult`).
    - Convex: Import generated document and ID types from `convex/_generated/dataModel` (`Doc<"topics">`, `Id<"topics">`).
- **Clean & Defensive Programming**:
  - Use early returns, guard clauses, and exhaustive union checks (`never`).
  - Model domain states with discriminated unions and `satisfies` operators.

## 10. Environment Variables, Secrets & Boundaries

- **Environment Variable Synchronization**:

  - Only variables intended for browser consumption may use the `NEXT_PUBLIC_` prefix.
  - Sensitive write tokens (`SANITY_API_WRITE_TOKEN`) and AI credentials (`GEMINI_API_KEY`) must NEVER be exposed via `NEXT_PUBLIC_` or imported into client components.
- **Never Commit Secrets**:
  - Never commit real credentials or private keys to version control.
